# 과제 제출 1초 전 ⏰

과제 제출 마감 직전의 혼란을 체험하는 **브라우저 기반 제한 시간 선택형 웹게임**입니다.
설치·로그인·백엔드 없이 `index.html` 을 열기만 하면 바로 플레이됩니다.
바닐라 HTML / CSS / JavaScript 로만 제작되어 **GitHub Pages** 에 그대로 배포할 수 있습니다.

> 마감까지 03:00. 화면을 미친 듯이 떠다니는 `최종.pdf`, `진짜최종.pdf`,
> `최종최종_이거임.pdf`, `절대열지마세요.zip` 사이에서 **진짜 제출 파일**을 찾아내세요.
> 폰트 깨짐, 용량 초과, 와이파이 끊김, 팀원의 마지막 수정본이 당신을 기다립니다.

## 🎮 한눈에 보는 게임

- **한 판 플레이 시간**: 약 2~4분 (Lv.1 제한 시간 3분)
- **장르**: 싱글 플레이 · 제한 시간 · 선택형 블랙 코미디
- **레벨 진행**: Lv.1 ~ Lv.5, 한 레벨을 클리어하면 다음 레벨이 열립니다(진행도 저장)
- **재미의 3요소**
  1. 여러 단서(폰트·이미지·용량·수정시간·팀원 최신본)로 **진짜 파일을 추리**
  2. 시간이 줄어드는 **긴장감** 속에서 계속 선택
  3. 대학생이라면 공감할 **황당한 사건과 10종 멀티 엔딩**
- **매 판 랜덤화**: 과목/과제, 파일 구성, 진짜 파일, 사건 순서, 업로드 오류, 엔딩 조건

## 🎚 레벨(난이도) 시스템

레벨이 오를수록 **제한 시간은 줄고, 파일·함정은 늘고, 사건은 잦아지고, 파일은 더 빨리** 날아다닙니다.
**진짜 파일을 제출에 성공하면 그 레벨을 클리어**하고 다음 레벨이 열립니다(진행도는 `localStorage`에 저장).

| 레벨 | 이름 | 제한 시간 | 파일 수 | 함정 | 특징 |
|---|---|---|---|---|---|
| Lv.1 | 신입생의 첫 과제 | 3:00 | 6~7 | 1~2 | 여유롭게 단서 읽는 법 익히기 |
| Lv.2 | 새내기 탈출 | 2:40 | 7~8 | 2 | 파일이 조금 더 많고 빠름 |
| Lv.3 | 중간고사 지옥 | 2:20 | 8~9 | 2~3 | 사건이 자주 터짐 |
| Lv.4 | 팀플의 저주 | 2:00 | 9~10 | 3 | 팀원 카톡 폭탄, 멘탈 관리 |
| Lv.5 | 졸업작품 마감 | 1:40 | 10~11 | 3~4 | 파일이 총알처럼 날아다니는 최종 관문 |

- 시작 화면의 **난이도 선택** 버튼으로 열린 레벨을 직접 고를 수 있습니다(잠긴 레벨은 🔒).
- 큰 `이어서 도전` 버튼은 **열린 최고 레벨**에서 바로 시작합니다.
- 엔딩 화면에서 클리어 시 `다음 레벨`, 실패 시 `이 레벨 다시 도전` 버튼이 나타납니다.
- 레벨 값은 [`data.js`](data.js) 의 **`LEVELS`** 배열에서 자유롭게 추가·수정할 수 있습니다.

- 스크립트는 **상대 경로**로 로드되어 GitHub Pages 하위 경로에서도 문제없습니다.

## ▶ 로컬 실행 방법

가장 간단한 방법은 **`index.html` 을 브라우저로 그냥 여는 것**입니다. 그거면 끝입니다.

```

# 방법 2) 로컬 서버로 열기 (권장 — 일부 브라우저의 file:// 제약 회피)

python -m http.server 8000
#   또는:  npx serve .
# 브라우저에서 http://localhost:8000 접속
```

> 💡 효과음은 브라우저 정책상 **첫 클릭(제출 시작 버튼) 이후**에 재생됩니다.

## 🚀 GitHub Pages 배포 방법

1. 새 GitHub 저장소를 만들고, 이 폴더의 파일들을 **저장소 루트**에 올립니다.
   ```
   git init
   git add .
   git commit -m "과제 제출 1초 전 게임"
   git branch -M main
   git remote add origin https://github.com/<사용자명>/<저장소명>.git
   git push -u origin main
   ```
2. GitHub 저장소 → **Settings → Pages** 로 이동
3. **Source** 를 `Deploy from a branch`, **Branch** 를 `main` / `/ (root)` 로 지정하고 저장
4. 1~2분 뒤 `https://<사용자명>.github.io/<저장소명>/` 에서 바로 플레이 가능

> 모든 경로가 상대 경로라 `<저장소명>` 하위에 배포돼도 정상 동작합니다.
> 프로젝트 파일을 저장소 루트가 아닌 하위 폴더에 두었다면 그 폴더까지 URL에 붙입니다.

## 🧠 주요 게임 로직 설명 (`game.js`)

| 시스템 | 설명 | 관련 함수 |
|---|---|---|
| **상태(state)** | 남은시간·멘탈·팀원신뢰·교수의심·완성도·인터넷·플래그 등을 담는 객체 | `freshState()` |
| **파일 생성** | 파일 풀에서 6~8개를 뽑고, 후보 중 하나를 **진짜 파일**로 지정. 정답은 최신·정상 폰트·이미지 포함 등 좋은 단서 조합, 일부 가짜도 그럴듯하게 위장 | `generateFiles()` |
| **플로팅** | `requestAnimationFrame` 으로 파일 아이콘이 벽에 튕기며 이동. 마지막 30/10초에 속도 증가 | `loop()` |
| **타이머** | 1초마다 감소. 마지막 30초 경고 테두리, 10초 카운트다운·틱 사운드·타이머 확대 연출 | `tick()` |
| **랜덤 사건** | 16~26초마다 가중치 기반으로 사건 발생 → 모달로 선택지 제시 | `fireRandomEvent()` / `openModal()` |
| **파일 정보** | 선택한 파일의 단서와 위험 요소를 사이드 패널에 색상 구분해 표시 | `renderPanel()` |
| **제출/업로드** | 제출 버튼 → (마지막 선택) → 업로드 진행률. 99% 멈춤·중간 로그아웃 등 랜덤 사건. 취소·재시도 가능 | `onSubmitClick()` / `beginUpload()` / `stepUpload()` |
| **엔딩 판정** | 제출 여부·제출 파일·상태값·플래그를 `priority` 순으로 검사해 엔딩 결정 | `endGame()` |
| **기록/공유** | 엔딩을 `localStorage` 에 저장(엔딩 도감), 결과 문구를 클립보드로 복사 | `saveRecord()` / `copyResult()` |

### 상태 변수 요약
`time`(초) · `mental` · `teamTrust` · `profSuspicion` · `completeness`(0~100) ·
`net`(`online`/`weak`/`off`) · `flags`(선택에 따른 특수 플래그).
모든 게이지는 0~100 범위로 자동 클램프됩니다(`clamp`).

## ➕ 사건(이벤트) 추가하는 방법

`data.js` 의 **`EVENTS`** 배열에 객체 하나를 추가하면 됩니다.

```js
{
  id: 'my_event',            // 고유 id
  kind: 'messenger',         // 'messenger' | 'error' | 'popup' (표시 스타일)
  who: '팀원 박OO',           // 모달 헤더에 표시될 발신자
  title: '카톡: 새로운 위기',
  body: '"교수님이 방금 조교한테 전화했대..."',
  once: false,               // true면 한 게임에 한 번만 등장
  weight: 1,                 // 뽑힐 확률 가중치 (클수록 자주)
  choices: [                 // 2~4개 권장
    { label: '대응 A (완성도↑ 시간↓)', effect: (s) => {
        s.completeness = clamp(s.completeness + 10);
        s.time -= 15;
        s.log('무슨 일이 일어났는지 로그에 남긴다.');
    }},
    { label: '대응 B (신뢰↓)', effect: (s) => {
        s.teamTrust = clamp(s.teamTrust - 12);
    }},
  ],
}
```

- `effect(s)` 안에서 `s.time`, `s.mental`, `s.teamTrust`, `s.profSuspicion`,
  `s.completeness`, `s.net` 을 바꾸고, `s.flags.xxx = true` 로 특수 플래그를 세울 수 있습니다.
- `s.log('문구')` 로 하단 사건 로그에 기록을 남깁니다.
- **업로드 중 사건**은 `UPLOAD_EVENTS`, **제출 직전 마지막 선택**은 `FINAL_CHOICES` 배열에 같은 형식으로 추가합니다.

## 🏁 엔딩 추가하는 방법

`data.js` 의 **`ENDINGS`** 배열에 추가합니다. `priority` 가 높은 것부터 검사합니다.

```js
{
  id: 'my_ending',
  priority: 55,              // 높을수록 먼저 판정 (겹치면 우선)
  cond: (c) => c.submitted && c.state.mental <= 10,   // 발동 조건
  title: '멘탈 가출 후 제출',
  emoji: '🫠',
  desc: '정신은 이미 집을 나갔지만 파일은 어떻게든 올라갔다.',
}
```

`cond(c)` 에서 사용할 수 있는 값:
- `c.submitted` — 제출 성공 여부(boolean)
- `c.submittedFile` — 제출한 파일 객체(`isCorrect`, `ext`, `wrongSubject`, `endingTag` 등)
- `c.timeout` — 시간이 다 되어 끝났는지(boolean)
- `c.state` — 게임 상태 전체(`completeness`, `teamTrust`, `flags` 등)

> ⚠ 맨 마지막 `timeout_default` 엔딩은 `cond: () => true` 라서 **항상 참**입니다.
> 새 엔딩은 반드시 그것보다 **높은 priority** 로 넣어야 발동합니다.
